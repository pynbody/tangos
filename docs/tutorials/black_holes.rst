Black holes
===========

Simulations that follow supermassive black holes add a new kind of object to the
database. This tutorial adds them for a ChaNGa simulation, then explores what
that gives you: the black holes themselves, links between them and their host
halos, and their accretion histories.

It uses ``tutorial_changa_blackholes``, a second run of the simulation in
:doc:`/tutorials/first_database`, from identical initial conditions but with
black holes and their feedback. Comparing the two runs halo by halo is the
subject of :doc:`/tutorials/crossmatching`.

.. note:: Before you start, make sure you have worked through
 :doc:`/tutorials/first_database`; this tutorial repeats its steps for the new
 simulation and then builds on them. The exploration that follows runs against
 the tutorial database (see :ref:`installation`), which already contains
 everything built here.

Adding the simulation and its black holes
-----------------------------------------

Download the `raw simulation data
<https://tangos.pontzen.uk/tutorials/tutorial_changa_blackholes.tar.gz>`_ and
unpack it beside ``tutorial_changa``, in the folder that
``TANGOS_SIMULATION_FOLDER`` points to. Then follow every step of
:doc:`/tutorials/first_database`, with ``tutorial_changa_blackholes`` in place of
``tutorial_changa``.

That gives you halos, their merger tree and their properties, but no black holes:
those come from a command of their own,

.. code-block:: bash

   tangos import-changa-bh --sims tutorial_changa_blackholes

which finds the black hole particles in each snapshot, adds each as an object of
type ``BH``, and links it to the halos it sits in. It is specific to ChaNGa, and
reads the black hole logs that ChaNGa writes beside the snapshots. If you use
Michael Tremmel's black hole implementation, run his pre-processing script first,
to produce the ``.shortened.orbit`` and ``.mergers`` logs from ChaNGa's raw output.

Like halos, black holes start with no properties. Calculate some with
``tangos write``, adding ``--type bh`` to say that it is the black holes you
mean, not the halos:

.. code-block:: bash

   tangos write BH_mass BH_mdot_histogram --for tutorial_changa_blackholes --type bh

``BH_mass`` is the black hole's mass at each snapshot, and ``BH_mdot_histogram``
its accretion rate between snapshots, stored in the same way as star formation
histories (see :doc:`/tutorials/histograms`). Both commands can run in parallel;
see :doc:`/how-to/parallel`.

Black holes and their hosts
---------------------------

Each timestep now holds black holes alongside its halos. They are numbered by the
simulation's own particle ID for the black hole, so a black hole keeps its number
from one snapshot to the next:

.. ipython::

 In [1]: import tangos

 In [2]: import pylab as p

 In [3]: timestep = tangos.get_timestep("tutorial_changa_blackholes/%960")

 In [4]: timestep.bhs.count()

 In [5]: bh = timestep.bhs[0]

 In [6]: bh

 In [7]: bh.keys()

Besides its own properties, each black hole has a ``host_halo`` link, to the
smallest halo it belongs to:

.. ipython::

 In [1]: bh['host_halo']

From the halo's side, two links lead back. ``BH_central`` links a halo to the
black holes it holds directly, outside any subhalo; ``BH`` links it to all the
black holes within it, subhalos included. A massive halo can hold many:

.. ipython::
 :okwarning:

 In [1]: halo = tangos.get_object("tutorial_changa_blackholes/%960/halo_1")

 In [2]: len(halo['BH']), len(halo['BH_central'])

Following either link from a halo with several black holes gives a value for each
of them, with a warning that the link is ambiguous. Usually you want one in
particular -- the most massive, or the one nearest the centre -- and
:ref:`live_calculation_recipes` shows how to pick it with ``link()``. Here, the
most massive:

.. ipython::

 In [1]: main_bh = halo.calculate(lambda: link(BH_central, BH_mass, "max"))

 In [2]: main_bh['BH_mass']

The accretion history
---------------------

``BH_mdot_histogram`` holds the accretion rate in 20 Myr bins, like the star
formation histories of :doc:`/tutorials/histograms`.

.. warning::

   ``tangos import-changa-bh`` does not currently link black holes from one
   snapshot to the next: it logs ``No merger file`` and skips that step. So in the
   tutorial database, as in any built with the current version, this history
   covers only the half Gyr stored at the final snapshot -- the plot below is zero
   before 2.74 Gyr for that reason alone -- and a black hole's
   ``BH_mass`` cannot be followed back through earlier snapshots.

.. The missing black hole time links are a stage 6 item in KNOWN_ISSUES.md (the
   importer looks for *.BHmergers where the data has .mergers, and behind that
   uses np.in1d, which current numpy lacks). When they are fixed and the tutorial
   database rebuilt, remove the warning above and check the plot and the text.

 In [1]: mdot = main_bh['BH_mdot_histogram']

 In [2]: t = main_bh.get_objects('BH_mdot_histogram')[0].x_values()

 In [3]: p.figure()

 In [4]: p.plot(t, mdot);
