Building your first database
============================

Every tutorial so far has queried a database that somebody else built. This one
builds it. You take the raw output of a simulation, plus whatever a halo finder
made of it, and end up with a tangos database you can query exactly like the
tutorial one -- your own halos, your own merger trees, your own images.

The walkthrough uses a small ChaNGa simulation with AHF halo catalogues,
because it is the tutorial dataset that includes gas and stars: images and star
formation histories work on it, and it has a companion run with black holes.
Everything here applies to any supported code and finder. Two of the steps --
importing the finder's own properties, and building the merger tree -- are the
only ones that depend on which finder you used, and each offers a tab for the
common choices. If your combination is not among them, see
:ref:`simulation_formats`.

.. note:: Before you start, make sure tangos is installed and knows where to
 put its database; :ref:`installation` covers both. Unlike the earlier
 tutorials, this one reads simulation snapshots, so you also need a reader for
 them -- for this dataset, pynbody (``pip install pynbody``).

 You also need somewhere to put the simulation data.
 ``TANGOS_SIMULATION_FOLDER`` names the directory tangos looks in; it defaults
 to your home directory. See :ref:`installation`.

Get the simulation data
-----------------------

Download the tutorial ChaNGa data and unpack it inside your simulation folder:

.. code-block:: bash

  $ cd $TANGOS_SIMULATION_FOLDER
  $ curl https://zenodo.org/record/5155467/files/tutorial_changa.tar.gz?download=1 | tar -xz

This is the slow part of the tutorial, and the only part that needs real disk
space; the tangos database built from it is a few tens of megabytes. (If you
later want every tutorial dataset, ``test_tutorial_build/build.sh`` in the
tangos repository fetches and builds them all, and warns you that it needs
about 35 GB.)

Add the simulation
------------------

.. code-block:: bash

  $ tangos add tutorial_changa

This takes a minute or so, with log messages scrolling past. Taking the command
apart:

* ``tangos`` is the command-line tool that administers a tangos database;
* ``add`` is the subcommand that adds a new simulation to it;
* ``tutorial_changa`` is the directory holding the simulation, relative to
  ``TANGOS_SIMULATION_FOLDER``.

Every tangos subcommand documents itself: ``tangos --help`` lists them all, and
``tangos add --help`` explains the options for this one.

What you have now is the *skeleton* of a database. tangos has found the
timesteps and the objects each one contains, and made a slot for every one of
them, but it has not calculated anything about them yet. You can see exactly
that by asking what the last run did:

.. code-block:: bash

  $ tangos recent-runs 1

.. code-block:: text

  ************************************************************
  Run ID =  1
  Command line =  /path/to/tangos add tutorial_changa
  Host =  jasmine
  Username =  app
  Time =  29/08/26 17:39
  >>>    1 simulations
  >>>    5 timesteps
  >>>    2707 halos

``recent-runs`` reports runs against *the database*, not runs of the
simulation: every command that writes to a tangos database leaves a record like
this one, which is the quickest way to confirm a long job did what you thought.
Your counts will differ from those above, since they depend on the dataset.

.. note::
   This step, and most of the steps below, can be
   :doc:`run under MPI </mpi>` to use more than one core. That matters little
   for a tutorial dataset and a great deal for a production simulation.

Import the finder's properties
------------------------------

Your halo finder has already measured things -- masses, radii, centres -- and
written them alongside the catalogues. Importing them costs nothing compared
with recalculating them, so it is the natural first thing to put in the
database.

This is the first of the two steps that depend on your halo finder. Pick yours:

.. tab-set::

   .. tab-item:: AHF
      :sync: ahf

      .. code-block:: bash

        $ tangos import-properties Mvir Rvir --for tutorial_changa

      The named columns are read out of AHF's ``.AHF_halos`` stat files.
      ``--for tutorial_changa`` says which simulation to apply this to, and can
      be omitted when the database holds only one.

Add your first property
-----------------------

Now tangos starts doing its own work. This is a *zoom* simulation: a small
region simulated at high resolution inside a coarser volume. Only the halos in
the high resolution region are worth studying, so the first thing to calculate
is which those are.

.. code-block:: bash

  $ tangos write contamination_fraction --for tutorial_changa

* ``tangos write`` is the command that calculates properties and stores them;
* ``contamination_fraction`` is a built-in property giving the fraction of a
  halo's dark matter particles that came from outside the high resolution
  region. ``tangos list-possible-properties`` shows everything available.

A halo with a contamination fraction near zero is clean; one near one is mostly
made of coarse particles and is an artefact of the zoom technique rather than
an object to do science on.

Now the interesting properties
------------------------------

With a way to tell the good halos from the bad, you can calculate the
properties you actually came for -- density profiles, images, and star
formation histories:

.. code-block:: bash

  $ tangos write dm_density_profile gas_density_profile uvi_image SFR_histogram \
      --with-prerequisites --include-only="contamination_fraction<0.01" \
      --include-only="NDM()>1000" --for tutorial_changa

Three of those options are worth understanding, because they are what make a
database like this affordable to build:

* ``--with-prerequisites`` calculates anything the requested properties depend
  on. A density profile needs an accurate centre and extent for the halo
  (``shrink_center`` and ``max_radius``), so those get calculated and stored
  too, without you asking.
* ``--include-only`` filters which objects are calculated, using the same
  :ref:`live calculation language <live_calculations>` you query with. Here two
  filters combine: a halo must be uncontaminated (less than 1% coarse
  particles) and must have more than 1000 dark matter particles. Below that, a
  halo is too poorly resolved for these properties to mean anything.
* Everything else is skipped entirely -- which is the point. Most halos in most
  simulations are not worth the cost of a density profile.

This is the slowest step in the tutorial. :doc:`/mpi` shows how to spread it
across the cores you have.

Errors here are normal
----------------------

The log will very likely contain messages such as ``Number of smoothing
particles exceeds number of particles in tree``. That is expected: it is what
smoothing over a handful of gas or star particles in a marginal halo looks
like.

tangos isolates an error in one object's calculation, reports it, and carries
on with the next. A failed property leaves an empty slot rather than stopping
the run, so a long build does not have to be babysat. If you would rather not
see them at all, tighten the ``--include-only`` filters.

What you have
-------------

A database describing your own simulation, indistinguishable in use from the
one the earlier tutorials queried. Everything in :ref:`quickstart`,
:ref:`time_series`, :ref:`live_calculations` and :ref:`webserver` now works
against it -- point ``TANGOS_DB_CONNECTION`` at it and explore.
