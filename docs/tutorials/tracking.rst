Tracking particles through time
===============================

Halos are not the only things worth following through a simulation. You might
pick out the gas that is dense at one moment and ask where it was before -- was
it accreted smoothly, or stripped from a satellite? -- or where it goes next.
tangos lets you define a *tracker*: a fixed set of particles, which it follows
from snapshot to snapshot and treats much like a halo. ``tangos write`` calculates
properties for trackers just as it does for halos, so you can follow how the
tracked material evolves.

.. note:: Before you start, make sure you have worked through
 :doc:`/tutorials/first_database`, and still have its simulation files: making a
 tracker reads the particle data, and so does calculating its properties.
 Because of that, the examples on this page are shown without their output.

Choosing the particles
----------------------

A tracker is made from a set of particles, which you choose with pynbody. Here,
all the gas in halo 1 at the final snapshot that is denser than 0.1 protons per
cubic centimetre:

.. code-block:: python

   import tangos, pynbody

   particles = tangos.get_object("tutorial_changa/%960/halo_1").load()
   particles.physical_units()
   dense_gas = particles.gas[pynbody.filt.HighPass('rho', "0.1 m_p cm^-3")]

Then make the tracker:

.. code-block:: python

   from tangos import tracking
   tracker_number = tracking.new("tutorial_changa", dense_gas)

:func:`tangos.tracking.new` records the particles' IDs, adds a tracker object to
every timestep of the simulation, links each to the next, saves all of that to
the database, and returns the tracker's number -- 1, for the first tracker in a
simulation. The tracked particles at an earlier snapshot are then:

.. code-block:: python

   tangos.get_object(f"tutorial_changa/%832/tracker_{tracker_number}").load()

These are the same particles, wherever they were at that time -- not the gas that
is dense at that snapshot, but the gas that *will be* dense at the final one.
Choosing particles at an early snapshot instead follows them forwards, to where
they end up.

Calculating properties
----------------------

Trackers take properties like any other object. From the shell:

.. code-block:: bash

   tangos write mean_rho --for tutorial_changa --type tracker

``mean_rho`` is a built-in property: the mean density of the gas particles, in
protons per cubic centimetre. Like the properties with several names in
:doc:`/tutorials/custom_properties`, it is calculated together with
``mean_temp``, their mean temperature, which is stored too. ``--type tracker`` tells ``tangos write`` to
calculate for trackers rather than halos. Any property works, including your own
(see :doc:`/tutorials/custom_properties`): tangos hands the tracked particles to
the calculation, which need not know it is working on a tracker rather than a
halo.

Following the tracked gas
-------------------------

Trackers are linked through time like halos, so the methods of
:ref:`time_series` follow them:

.. code-block:: python

   import tangos, pylab as p
   tracker = tangos.get_object("tutorial_changa/%960/tracker_1")
   time, rho = tracker.calculate_for_progenitors(lambda: t(), lambda: mean_rho)
   p.semilogy(time, rho)

The gas was far less dense before. When this page was checked, the tracked gas
had a mean density of 31 protons per cubic centimetre at the final snapshot, and
about a tenth of that 0.43 Gyr earlier, at the previous one.

Trackers also appear in the web interface, in a table of their own beside the
halos on each timestep's page (see :doc:`/tutorials/webserver`).

.. note::

   Inside tangos, a black hole (see :doc:`/tutorials/black_holes`) is a kind of
   tracker, following its one particle. So in a simulation with black holes,
   :attr:`TimeStep.trackers <tangos.core.timestep.TimeStep.trackers>` includes
   them, and the trackers you make are numbered after the black holes, so are
   not small integers.

.. seealso::

   :mod:`tangos.tracking` and :class:`~tangos.core.tracking.TrackData` in the API
   reference, for making trackers from particle IDs you already have.
